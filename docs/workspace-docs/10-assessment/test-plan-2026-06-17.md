## 0. Nguyên tắc
- **Happy-path là lớp quan trọng nhất** (nhiều hệ thống "đẹp UI nhưng sai logic" vì thiếu lớp này).
- Mỗi bug tìm thấy → tạo Issue fix riêng (test KHÔNG tự sửa code).
- Test phải **chống hồi quy** (regression) + chạy trong CI gate.
- Ưu tiên dữ liệu **production-like / bẩn** (môi trường nội bộ thường sạch hơn thực tế).

## 3. Checklist theo loại màn hình (áp khi viết test từng màn)
- **Form (tạo/sửa):** hiển thị (đủ trường/label/placeholder/required */tooltip) · validation (rỗng/đúng/sai-format/đặc-biệt/TV-có-dấu/emoji/rất-dài/min/max/null/whitespace) · nghiệp vụ (bắt buộc/phụ-thuộc-field/auto-calc/enable-disable) · submit (thành công/thất bại/double-click/mất-mạng/refresh) · UI (loading/error/success/responsive).
- **List/Table:** đúng cột/data/format · sort (ASC/DESC/multi) · filter (đơn/kết-hợp/rỗng) · search (chính-xác/gần-đúng/TV/đặc-biệt) · pagination (đầu/cuối/đổi-size) · action (edit/delete/view/export) · perf (100/1k/10k).
- **Detail:** mapping đúng/null · trạng-thái hiển-thị + nút-theo-trạng-thái (vd Draft→sửa, Approved→khóa) · điều hướng.
- **Workflow nhiều bước:** luồng chuẩn · luồng ngược · luồng lỗi (bỏ bước/refresh/session-hết-hạn) · mọi chuyển trạng thái.
- **Dashboard:** số liệu (tổng/công-thức/đồng-bộ-BE) · filter (ngày/tháng/năm) · chart (đúng/tooltip/empty).
- **Auth:** login đúng/sai · security (SQLi/XSS/brute-force) · session (logout/token-hết-hạn/refresh).
- **Phân quyền:** theo vai trò → Menu(thấy?) · API(gọi được?) · UI(thấy nút?) · Action(làm được?).
- **Upload:** loại (PDF/Excel/Word/Image) · size (nhỏ/max/quá) · nội dung (lỗi/rỗng/sai-cấu-trúc) · mất-mạng giữa upload.
- **Import/Export:** import (đúng/thiếu-cột/thừa-cột/data-lỗi) · export (đúng-data/đúng-filter/UTF-8/dấu-TV không lỗi font).
- **Responsive:** 320/375/414 (mobile) · 768 (tablet) · 1366/1920 (desktop) → tràn chữ/vỡ layout/nút-bị-che/scroll-ngang.
- **Dark/Light:** màu chữ/nền/border/modal/tooltip/dropdown/toast/validation-message · toggle KHÔNG mất state.
- **API integration:** 200/201 · 400/401/403/404/500 · timeout/slow/retry.

## 8. Phương pháp test NÂNG CAO đề xuất (ngoài 10 lớp tối thiểu)
> Bổ sung cho hệ thống bệnh viện (rủi ro tiền/lâm sàng/pháp lý). Tạo epic riêng khi user duyệt.
1. **Visual-regression** (Playwright `toHaveScreenshot`/Percy): auto-diff pixel UI → bắt vỡ giao diện ngoài ý muốn (gắn evidence §7).
2. **Accessibility a11y** (axe-core): WCAG/keyboard/screen-reader/contrast — NV y tế dùng lâu, độ tương phản (đã chạm ở dark-mode).
3. **Contract testing** (Pact / OpenAPI validate): chốt hợp đồng FE↔BE + cổng ngoài **HL7/BHXH/FHIR** → bắt drift contract (gắn API-2 #193).
4. **Property-based / fuzz** (input ngẫu nhiên có ràng buộc): logic tiền/liều/ngày — phủ biên mà manual bỏ sót.
5. **Mutation testing** (Stryker): đo CHẤT LƯỢNG bộ test (test có thực sự bắt bug không), không chỉ coverage %.
6. **Golden-file / snapshot** cho output: **BHXH XML, hoá đơn, phiếu in** so với baseline đã duyệt.
7. **Chaos / fault-injection**: giết DB/PACS/gateway/Redis giữa luồng → kiểm resilience (gắn LT #265, transaction #187).
8. **Security: SAST/DAST + scan**: OWASP ZAP (DAST), `npm audit`/Snyk (deps), **gitleaks** (secret-scan — gắn SEC-3 #182), IDOR/authz (gắn #270).
9. **Load nâng cao**: soak (rò rỉ bộ nhớ chạy nhiều giờ) · spike (đỉnh đột ngột giờ cao điểm) · stress (tìm điểm gãy) — ngoài load cơ bản #223.
10. **Reconciliation / data-integrity**: tổng giao dịch = sổ cái; tồn kho khớp xuất-nhập; tiền không thất thoát (gắn money #187-190).
11. **Audit-log verification**: mọi thao tác nhạy cảm (patient/tiền/đơn) ĐỀU sinh log đúng (gắn AUDIT-1 #198).
12. **Backup/Restore + DR drill**: khôi phục từ backup chạy được, đúng dữ liệu (gắn backup-management).
13. **Synthetic monitoring (prod)**: giao dịch tổng hợp định kỳ trên prod + alert (bắt lỗi sớm sau deploy).
14. **Test-data management**: bộ dữ liệu production-like ẩn-danh + factory/builder + seed ổn định (giảm flaky).
15. **Risk-based + regression-selection**: ưu tiên test theo rủi ro; chỉ chạy test bị ảnh hưởng bởi diff (tăng tốc CI).
16. **Localization/i18n**: dấu tiếng Việt/encoding/định dạng ngày-số/font in (đã có ở T12, nâng thành chuẩn).
17. **Exploratory (session-based)**: charter có kịch bản cho tester người thật — bắt lỗi máy bỏ sót.
18. **Usability với NV lâm sàng thật**: đo thời gian/thao-tác-thừa/nhầm lẫn (UI đúng logic nhưng "khó dùng").

> Epic nâng cao đã tạo: **T17-T34 = #272-289**.

## 9. Quy trình BUG → FIX-TASK (BẮT BUỘC mọi phiên/máy) + DoD task test
> Chủ rule: `CLAUDE.md` mục "Quản lý plan/task". Áp cho MỌI task test.
- Khi test gặp **bug/lỗi/vỡ-UI** → tạo NGAY 1 Issue **fix** mới: tiêu đề nêu **rõ lỗi gì + màn/nghiệp vụ**; body = mô tả + **bước tái hiện** + **evidence (ảnh)** + kỳ-vọng-vs-thực-tế; label `bug` + module.
- **Liên kết 2 chiều**: fix ghi "Phát hiện từ #<test>"; comment ngược task test "Bug → #<fix>".
- **Vỡ UI** (responsive/dark/layout) cũng tạo fix-task để sửa sau (theo evidence §7).
- **★ DoD task test**: task test CHỈ `DONE` sau khi **MỌI bug nó tìm ra đã có fix-task tạo XONG (đầy đủ thông tin) + liên kết**. Còn bug chưa có fix-task đầy đủ → KHÔNG done test.
